# 地址空间与判读

## 7 位地址范围

I2C 规范把 7 位地址分成三段：

| 区间 | 用途 |
| --- | --- |
| `0x00`–`0x07` | 保留：general call、CBUS、HS-mode master code |
| `0x08`–`0x77` | 普通从机可用区间（脚本默认扫描范围） |
| `0x78`–`0x7F` | 保留：10 位地址前缀 |

- 扫描默认 `0x08-0x77`，共 112 个地址。
- 保留地址回 `ack` 几乎总是意味着地址算错、接线串扰或桥的上拉异常，不要当成"发现设备"上报。
- 10 位地址设备不在本脚本覆盖范围内：它需要先发 `0x78`/`0x79` 前缀，探测方式与 7 位不同。

## 传输帧里的地址

`/sys` 目录名和部分 datasheet 用"左移一位后含读写位"的形式。`1-0068` 表示总线 1、地址 `0x68`：`0x68 << 1 = 0xD0`（写）/ `0xD1`（读）。脚本已统一还原为 7 位。

## 探测方法

脚本优先用**零长度写**：

1. `ioctl(fd, I2C_RDWR)`，一条 `i2c_msg`：`addr`、`flags=0`（写）、`len=0`。
2. 设备回 `ACK` → 该地址有从机；回 `NAK` → 无从机。
3. 总线上不出现任何数据字节，所以对寄存器指针无副作用。

若适配器拒绝零长度传输（`ENOTTY`/`EOPNOTSUPP`/`EINVAL`），降级为：

1. `ioctl(fd, I2C_SLAVE, addr)` 选中从机。
2. `read(fd, 1)` 读 1 字节。

降级路径会**真的触发一次读事务**，某些设备会因此推进内部状态机或返回错误码。脚本会写 warning，汇报时必须转达。

## errno 对照

| errno | 脚本归类 | 含义 |
| --- | --- | --- |
| `ENXIO` (6) | `nak` | 无设备应答，最常见 |
| `EREMOTEIO` (121) | `nak` | 同上，部分适配器用这个值 |
| `EBUSY` (16) | `busy` | 地址已被内核驱动绑定 |
| `EACCES` / `EPERM` | `error: permission denied` | 权限不足，见 platform-support |
| `ENOTTY` / `EINVAL` | 触发降级 | ioctl 不被该适配器支持 |

`busy` ≠ 故障。它证明驱动已经接管该设备，去 `/sys/bus/i2c/devices/` 里查 `name` 和 `driver` 更直接。

## 常见地址（仅作推测参考）

**这些不是识别结果。** 同一个地址可能对应几十种芯片，地址可配置的器件经常被量产设计改成别的值。汇报时必须标注推测，并说明依据（用户提到的板子、`clients` 里的驱动名、丝印）。

| 地址 | 常见器件 |
| --- | --- |
| `0x0A` | SSD1306 OLED（SA0 高） |
| `0x1E` | HMC5883L / LSM303 磁力计 |
| `0x20` / `0x21` | PCF8574 / PCF8575 GPIO 扩展 |
| `0x27` / `0x3F` | PCF8574 LCD 背板 |
| `0x28` / `0x29` | BMP280/BME280（SDO 低）；`0x29` 也可能是 TSL2591、VL53L0X |
| `0x3C` / `0x3D` | SSD1306 / SH1106 OLED |
| `0x40` | INA219/INA260、SHT3x、HTU21D、PCA9685 |
| `0x48`–`0x4B` | ADS1115/ADS1015（四个 ADDR 组合）、LM75、PCF8591 |
| `0x50`–`0x57` | 24Cxx EEPROM；`0x53` 常见 ADXL345 |
| `0x5A` / `0x5C` | MPR121、MLX90614、APDS9960、BH1750 |
| `0x68` | DS1307/DS3231 RTC、MPU6050、ITG3205（RTC 与 IMU 撞地址很常见） |
| `0x69` | MPU6050 AD0 高、SCD30 |
| `0x70`–`0x77` | TCA9548A 多路复用器、HT16K33 数码管；`0x76`/`0x77` 也常见 BME280/BME680 |

## 多路复用器

`0x70`–`0x77` 若出现，说明总线上可能有 TCA9548A 之类的 mux。mux 后面的设备在选中通道前**不可见**，直接扫主总线会漏。遇到 mux 先说明这一限制，再让用户决定是否走 `hardware-controller` 做通道切换。

## 撞地址

同一总线上两个设备地址相同会互相干扰，表现为随机 `nak` 或数据错乱。识别到疑似撞地址（如 `0x68` 同时像 RTC 和 IMU）时，提示用户核对 ADDR 引脚和 `clients`。

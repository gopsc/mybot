# TSan 并发用例名单（单一来源，F3-5 / C10）
#
# 谁读它：
#   - .gitlab-ci.yml 的 gate:tsan：逐条跑 build-tsan/mybot_tests <名字>；
#   - test/run_all_selftest.sh：**双向**机械核对——名单里每个名字在
#     test/cpp/test_daemon_concurrency.cpp 里至少命中一条 TH_TEST，且反过来该文件里
#     每条 TH_TEST 都被名单某条覆盖。
# 为什么单列：此前 CI 与单测文件两处手抄同名清单，改一处忘一处就静默少跑
# （或跑一个不存在的名字——测试入口对零匹配返回 1，不会假绿）。
# 为什么两个方向都要核：「零匹配返回 1」只堵住了名单写错名字，堵不住**名单少一条**。
# 新加一条并发用例而名字不含任何现有条目时，gate:tsan 照常全绿，那条用例从来没在 TSan
# 下跑过——而它恰好是最可能带数据竞争的那条（新写的）。反向核对就是这个缺口的机械防线。
# 格式：每行一个**前缀**（测试入口按子串过滤，故中段命中也算覆盖）；# 开头与空行忽略。
daemon_concurrent
daemon_multi_runner
daemon_stop_and_exit

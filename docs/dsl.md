# DSL 参考：结构脚本与动作脚本

> 本文是 bot4cj 两类 DSL 的完整参考：结构脚本 `.sql` 声明硬件结构与调用链，动作脚本 `.mt` 以行列式 DSL 编排动作。[README](../README.md) 只留入口链接，语法细节以本文为准。

## 结构脚本（.sql）

由内置 SQL4cj 解析器（`src/sqlparse.cpp`）解析，支持 `--` 行注释与 `/* */` 块注释。一组 `CREATE TABLE / INSERT INTO`：每张表对应一类硬件（表名即矩阵名，决定加载哪个驱动，`modules/<矩阵名>.lua`），每行 INSERT 就是一个实例：

```sql
CREATE TABLE I2C (name String, path String);
INSERT INTO I2C (name, path) VALUES ('i2c-1', '/dev/i2c-1');

CREATE TABLE PCA9685 (name String, I2C String, address String);
INSERT INTO PCA9685 (name, I2C, address) VALUES ('pca9685-0', '$i2c-1', '0x40');

CREATE TABLE Servo (name String, max String, min String, offset String,
                    controller String, channel String);
INSERT INTO Servo (name, max, min, offset, controller, channel)
  VALUES ('s1', '90', '-', '-', 'pca9685-0', '0');   -- 左下水平关节
```

要点：

- `-` 是占位符，继承上一行同列的值（**首个数据行例外**：没有上一行可继承，`-` 原样保留为字面值、不填充，含义由消费方决定）
- `I2C` 列以 `$i2c-1` 引用上方定义的总线（引用列必须 `$` 前缀，裸名一律按字面值）
- 注释整行 INSERT 即可下线一个硬件实例；报错会指明是哪张表、哪一行、哪一列
- **INSERT 的列名清单决定「哪个值属于哪一列」，值按列名落到建表声明序**（2026-09-20 审计 C3）。`INSERT INTO Timer (delay, name) VALUES (50, 'timer-0')` 与 `(name, delay)` 写法等价，列序写反不会错列。三条硬约束（违规在解析期报错，不再静默错位）：列名必须在建表声明里存在（`no such column`）、同一列不得写两次（`listed twice`）、每列都必须给值（`missing value for column`，要继承上一行就显式写 `-`）
- 列类型支持 `String` / `Number`：值一律以文本驻留（`MatrixObject` 只存 String），`Number` 目前仅在**解析期**对字面量做一次数值校验（整数/小数/带符号/科学计数法合法，空值与 `nan`/`inf` 拒绝），不做运行期类型转换；校验按 INSERT 的列名匹配声明列，报错形如 `Column 'delay' of table 'Timer' is declared Number, but value 'abc' is not numeric.`
- **方言只认七条语句**：`CREATE TABLE` / `INSERT INTO` / `SELECT * FROM 表;` / `SHOW TABLES;` / `DELETE FROM 表;` / `DROP TABLE 表;` / `UPDATE 表 SET 列 = 值 [, ...];`
  - **SELECT** 仅在 agent 的 `query_sql` 与 REPL `/sql` 里可用（只读，见 [agent.md](agent.md)）。
  - **SHOW TABLES** 同样只读、同样只在 `query_sql` 与 REPL `/sql` 里可用：列出当前结构的**全部表名与数据行数**（数据行 = 除列头外的行数），形如 `SHOW TABLES (2):` 后逐行 `  表名 (N 行)`。**不带 `WHERE`/`LIKE`**（本方言取向「能一句话说清就够」，要筛某张表的行请用 `SELECT * FROM 表 WHERE ...`）。agent 模式下它还会列出宿主**自动注入**的 `Camera` 表——这在结构脚本摘录里看不到，是「当前到底有哪些表」的唯一权威答案。
  - **DELETE**（删**行**）、**DROP**（删**表**）与 **UPDATE**（改写**行**）都是**带电变更**：
    只在 REPL `/sql` 与 agent 的 `apply_sql` 里可用（需 `--agent-hot-sql`），在结构脚本 `.sql`
    文件里出现会在解析期报错（机器人尚未上电，没有可变的结构）。
  - **SELECT / DELETE / UPDATE 可带等值条件**（2026-09-23）：`WHERE 列 = 值`，多条件以 `AND` 连接
    （`WHERE 列1 = 值1 AND 列2 = 值2`）。按 `inherited` 显示值（`-` 继承解析后）做**精确文本比较**，
    数值按文本比（`'0x40'` ≠ `'64'`，已知边界）；比较运算符、`OR`、`IN` 不在方言内。
    列不存在报 `has no '...' column`；SELECT 0 行命中输出列头 + `（0 行匹配）`，
    DELETE / UPDATE 0 行命中**报错**（`no row matches, nothing was ...`）——删除与改写都是
    不可逆的物理操作，"已生效但什么都没发生"会让操作者以为器件已摘除/已改写。
    **`DROP` 不带 `WHERE`**：它是 DDL、作用于整张表
    （见下节）；要确认删对了表或按条件删一部分行，先用 `SELECT * FROM 表 [WHERE ...]` 查看。
- **热删除（`DELETE FROM`）的安全边界**（2026-09-23）：删除 = **当场逆序断电并摘除**器件，
  物理不可逆（没有回滚，已掉电的器件不会因后续报错而复电）。写入前先跑完所有校验，
  故拒绝一律发生在动第一个器件之前、活体一字未动：
  - 被别的行以 `controller` / `trigger`（含 `controller2` 这类编号列）、`$name` 引用或
    `$(...)` 表达式引用着的变量**拒绝删除**，报错点名「哪张表哪一行的哪一列引用了它」。
    这些引用在框架内部是终身缓存的裸指针，删掉被引用者即悬垂指针。要让一个器件下线，
    先删引用它的行（或把相关行写在同一条语句/同一批里一起删——判据看的是**删除之后**的视图）。
  - 删除同样跑一遍全结构判据（单消费者等），故「删掉总线而守护仍在用同一 `path`」这类
    物理耦合会被拦下。
  - 条件写错、命不中任何行时报错而不是静默成功。
  - 极少数情况下物理 `destroy` 本身失败（I2C 写失败、器件不响应）：此时**立即中止**后续删除，
    并如实报出「已删除 N 个（名单）、M 个未删除」——结构与注册表只反映已成功摘除的部分，
    未删的行保持原状。修好成因后对剩余项重发 DELETE 即可。
- **整表撤下（`DROP TABLE`）的安全边界**（2026-09-23）：`DROP TABLE 表;` = DELETE 的
  「全表行」+「摘表壳」两步——该表**全部**硬件变量当场逆序断电并撤出注册表，表壳（列头）连同该表
  的元数据提供者与守护登记一起从结构里消失。因而上面热删除的每一条安全边界（引用完整性、全结构
  判据、`destroy` 中途失败如实报数、结构脚本内出现即拒绝）都原样适用；此外：
  - **不带 `WHERE`**（标准 DDL 语义，作用于整张表）：WHERE 是 DML 的行级筛选，加在 DROP 上会
    「长得像在筛行、实际却整表删」。误写 WHERE 在**解析期**就被词元级报错拒绝（`Token WHERE`）、
    活体一字未动。要按条件删**一部分行**请用 `DELETE`；要确认删对了表，先 `SELECT * FROM 表 WHERE ...` 看一眼。
  - **空表可撤**：表里没有数据行（只有列头）也照样撤下——这是合法操作，不按 DELETE 的「0 命中报错」处理。
  - **一次批次内 DROP 必须是针对该表的唯一动作**：与本批次的 `INSERT`/`DELETE`（改行）或再次
    `CREATE`（同名重建）混在同一批会被拒绝——拆成两批即可。「本批次 `CREATE` 后又 `DROP` 同一张表」
    有专门路径：整表从未装配，最终净效果为空。
  - **`DROP` 之后可同名重建**：表名不再冲突，随后 `CREATE TABLE` 同名表会装配出全新变量（这是 DROP
    才打开的语义面；重建请用新的 `name` 列取值，否则会与残存变量重名）。
  - **`Action` 表不可 DROP**（瞬态表，行只被重放、从不注册成硬件变量），报错点名这一点。
  - 边界实现注记：表壳从结构容器（`std::deque`）上 `erase` 会让其后元素引用失效，故撤表后存活表的
    元数据提供者会被按表名**重锚定**——这是整表撤下才有的一条不变式。
- **热更新（`UPDATE 表 SET 列 = 值 [, ...] [WHERE ...]`）的安全边界**（2026-09-23）：语义是
  **断电重建**，不是原地改值——命中行按「DELETE（当场逆序断电摘除）+ INSERT（改后行重新装配
  上电）」两条既有路径执行，改写瞬间器件会断电重置。`name` 列可以改（= 换名重建：旧名消失、
  新名装配，新名不得与存活变量重名）；其余列照常改值。无 `WHERE` = 改写全部数据行。
  - **被引用即拒改**：命中行被别的行以 `controller` / `trigger` / `$name` / `$(...)` 引用着时，
    整批拒绝并点名引用方（与热删除同一条引用完整性防线——改写 = 摘除旧件，悬垂指针判据一致）。
    改写行自己的新值若引用**本批次将删/将改写**的变量，同样在预检拒绝（含改回自己的旧名）。
  - **批内独占**：`UPDATE` 与该表的其它行级语句（`INSERT` / `DELETE` / 再次 `UPDATE`）不得同批，
    两个方向都被拒绝；对本批次 `CREATE` 出来的表也不可用（行从未装配，把 INSERT 写成想要的
    样子即可）。拆成两批/两次调用就行。
  - **执行序是先删后建**：与 DELETE+INSERT 的「先建后删」不同，UPDATE 批次先物理摘除旧件、
    再装配新件——新旧器件不会短暂并存抢同一物理器件。代价是**失败窗口**：预检全过之后若新件
    装配/上电失败（如 `$` 引用不存在、驱动 build 失败），新件整批回滚断电，**已摘旧件不复原**
    （destroy 是物理断电），错误会点名「哪些变量已断电摘除且未能重建」——按需要的值重新
    INSERT 即可恢复。
  - 生效摘要如实报三段：「已热更新 N 行（断电重建）」+ 删除/新增计数（同一物理事实的两个
    维度，审计 `apply_sql` 的 summary 同源）。
  - `Number` 列的 SET 值与 INSERT 同一判据：数值字面量或 `'$(表达式)'`（带引号——词法器把
    `(` 当分隔符），解析期即校验。

**引号字面量**：`'` / `"` 包裹的值整体按字面解析——引号内的 `--`、`/* */`、`;`、`,`、`(`、`)`、`=` 与空白都是**数据**而非注释/分隔符（注释只在引号外生效）。同类引号用标准双写转义：`'it''s'` 是一个值 `it's`。这是 1.x 起修复的词法器行为，有负值回归守门（`robots/test/sqlquote.sql`、`lexer_doubled_quote_escape_is_literal_quote`）。

## 动作脚本（.mt）

用一张表格描述一帧一帧的动作，表头是「硬件变量.参数」，每行一帧，逐行播放：

```mt
# 行动矩阵为硬件变量输入参数
@Action
s1.A  s2.A  spk.F  spk.delay;   # column name
  45    45     10      200;      # stand
  90     -      -       20;      # left-behind
@
```

- 可内联 `@Alias` 别名矩阵（如把 `s1.A` 写成 `s1.angle`）；`@Vars` 命名数值变量同构（列 `name`/`value`），也可内联
- **设备列也可写 `@Alias`**（解析穿透，一层为止）：列头设备位若是别名，派发前解析到别名值命名的驱动/守护再播放——别名是**名字绑定**而非播放目标。用途是片段复用：模板的设备列写别名，主脚本改一行绑定值即换目标设备（见 [@Merge 主从覆盖](#merge-内联归并运行端动作脚本合并)）：

  ```mt
  @Alias
  name  alias;
     leg  s1;
  @

  @Action
  leg.A;      # 解析为 s1.A 播放；leg 指向 s2 时同一份脚本落在 s2 上
    45;
  @
  ```

  规则与负值契约：

  - 别名必须命中**非标量**硬件变量；指向未定义名字、或又一个别名（一层为止）都清晰报错
  - `@Vars` 是数值常量，放设备位直接拒绝
  - 不同列头解析出**同一 (设备, 参数)**（如别名与真名各写一列）在派发前报错——逐行静默覆盖不可接受，这也是归并期设备查重（按列头文本）的运行端补充层
  - 真名拼写错误仍在派发期按行号报错，与从前一致
- 单元格可写 `$(<表达式>)`（见 [表达式](#表达式-)）：数据格如 `$(v1+v2+10)`（`-` 继承会沿用上一行的解析结果）；**列头两个位置也可写**——设备位 `$(pfx+n).test` 拼出目标设备、参数位 `dev.$(a1+a2)` 拼出参数名；`+` 出现别名即拼接，数据格产物为文本时成为**文本参数**（与 SQL 元数据列同型）。求值都在派发期：片段复用时改绑后的别名值、变量真值以运行时为准
- 结构与动作两侧都可定义别名/数值变量：`@Alias` 同名时**动作脚本的定义覆盖**（打印覆盖日志）；**`@Vars` 不允许覆盖**——它的数值经 `$`/`$(...)` 引用列进入硬件参数，动作脚本同名覆盖等价于改写结构定义（`.mt` 内联 `@Vars` 只能使用新名字，引用结构 Vars 读取不受影响）
- 同一动作脚本内重复定义同名别名（或数值变量）报错（负值契约）
- **动作脚本内联的 `@Alias`/`@Vars` 是「本次执行」的局部绑定**（2026-09-20 重构阶段 1）：作用域 = 一次动作脚本的执行，执行结束（含**以报错收场**）即整体回滚——结构定义与结构脚本的绑定一字不动。此前它们是进程级的：会永久遮蔽同名结构变量，且 agent 长驻模式下会跨脚本残留（脚本 A 定义的别名对脚本 B 可见）并持续占用内存。
  - **这是唯一的破坏性语义变更**：若你依赖「前一个动作脚本定义的别名给后一个脚本用」，请把该别名写进**结构脚本**（`.sql` 的 `@Alias` 表），或用 `@Merge` 主从覆盖在本次执行内表达。
  - 同一次执行之内行为完全不变：`@Merge` 归并来的别名、设备列别名解析、`$(...)` 引用都照旧。

## 捕获格 `$var=field`（返回值字段赋值，2026-10-10）

`@Action`（及 `@if` 块体）的数据格除数值、`-` 继承、`$(...)` 之外，还可写 `$<var>=<field.path>`：把**本格所在列设备**本帧 `play` 返回值里的某个字段，赋给 `@Vars`/`@Alias` 变量——「读一个传感器、把读数存进变量、后续帧/后续块再用」就地可表达：

```mt
@Action
imu.reading;
  $x=reading;        # 第 1 帧：play imu（不传参），把返回表的 reading 字段存进 @Vars x
  $x=reading;        # 也可换字段/换变量
@

@if(x>5)             # 捕获的 x 随即可被 @if 条件消费
s1.A;
  90;
@
```

- **锚定本格列的设备**：`$var=field` 写在 `dev.param` 列下，就从本行 `dev` 的 `play` 返回取值（一行多设备列各取各的，不串台）。
- **捕获格不传参**：该格不再向 `dev` 投递参数（列头 `param` 位对捕获格无意义，只作列标识/查重键）；但若某设备本行**只有捕获、没有普通参数**，它仍会被 `play` 一次（以空参数触发一次读取/调用），否则无从拿到返回值。
- **字段路径支持点号嵌套**：`$t=data.temp` 逐层下钻返回表（`data` 子表的 `temp` 字段）。中途非对象、或某段缺失 → 带行号+列头+捕获原文的响亮报错（halt-on-error）。
- **类型与作用域**：赋值经**会话覆盖层**落地（生命周期 = 一次 `run()`，含以报错收场时整体回滚，与内联 `@Alias`/`@Vars` 同一作用域）：
  - 目标已声明为 `@Vars` → 字段必须是数值（整数/小数），否则报错；已声明为 `@Alias` → 字段文本化（字符串原样、数值按 `%.15g`、布尔 `true`/`false`；对象/数组/null 拒绝）。
  - 目标是驱动/守护（非标量）→ 拒绝（它们没有可写的文本值）。
  - 目标**未声明** → 按字段类型自动新建（数值→`@Vars`、字符串→`@Alias`；布尔/对象/数组无法推断，报错提示先声明）。
  - 捕获**可遮蔽同名结构层定义**：写入会话层后，本次 `run()` 余下时间该名解析到被捕获值（含结构侧 `$name` 元数据引用，因表达式解析会话层优先），`run()` 结束回滚、结构定义一字不动。
- **唯一例外——flowRef 不可覆盖**：目标名若正被别的变量用作 `controller`/`trigger`，赋值被拒（把它变成标量会让派发按名查到别名、报出与真因脱节的错；这是安全不变式，不是策略）。
- **消费时机跨帧/跨块**：同一行内 `$(...)` 表达式在**捕获之前**求值（整行单元格先解析、再逐设备 play），故捕获的值只能被**后续行**的 `$(...)`、或**后续块**（`@if`/`@Action`）消费——「先读后用」按书写顺序天然成立。
- 回归：`capture_*`（`test/cpp/test_action_capture.cpp`）覆盖数值/文本捕获、嵌套路径、自动新建、供后续 `$(...)` 与 `@if` 消费、遮蔽结构层、以及缺失字段/非标量/类型不符/flowRef/坏形态各负值。

## `@if` 条件块（2026-10-10）

`@if(<条件>)` 是**带条件的动作块**：块体与 `@Action` 完全同构（列头 `<设备>.<参数>` + 数据行），**轮到该块执行时**求值一次条件——成立则把块体当 `@Action` 逐行派发；不成立则跳过该块（stderr 注记 `[if] condition not met: '<条件>', skipping N action row(s)`）并继续执行后续块：

```mt
@Vars
name  value;
   threshold  30;
@

@if(threshold>0)
s1.A;
  45;
@

@Action
s1.A;
  90;
@
```

- **与 `@Action` 按书写顺序交错执行**：「先做 A、条件满足再做 B」把 `@Action` 写前面、`@if` 写后面即可；展开层把（`@Merge` 归并后的）合并 `@Action` 锚在主脚本第一个 `@Action` 的书写位置，其余块原序透传
- **条件只引用 `@Vars`（数值）与 `@Alias`（文本）**，与 `$(...)` 同一套标识符解析：裸名即变量名，未定义响亮报错。**实时传感器值不在条件面**——按既定架构挂守护采样、由消费驱动决策（[docs/daemon.md](daemon.md)）；驱动/守护名出现在条件里按「不是标量变量」报错
- **条件语法**：`$(...)` 表达式引擎的全部算术（`+ - * / %`、括号、一元正负、字符串字面量）加上比较 `> < >= <= == !=` 与逻辑 `&& || !`（短路求值，优先级同 C：`&&` 高于 `||`、比较高于逻辑、算术高于比较）。**类型严格无隐式转换**：比较 `> < >= <=` 只收数值；`== !=` 同类可比（数值/文本/布尔）；`&& || !` 只收布尔——`@if(threshold)` 不是「非零即真」，要写 `@if(threshold>0)`
- **块头内不能有空格**（与 `$(...)` 同约束：矩阵解析把空白当分隔，`@if(a > b)` 会被切成块名 `if(a` 与数据行）——写成 `@if(a>b)`；条件里需要字面文本用双引号 `@if(mode=="auto")`（值内不得含空格；双引号/换行等控制字符写转义 `\"`、`\n`，见[表达式](#表达式-)的「转义」条）
- **求值时机是「轮到该块时」**：前面的块执行完后条件才求值（`@Vars`/`@Alias` 是静态值，此时机主要保证语义直白）；条件求值失败（未定义标识符、类型错、非有限值）按 halt-on-error 中止整个脚本
- **@Merge 片段里不支持**：片段的 `@Action` 按相位归并进主脚本，`@if` 没有独立执行位置——出现在片段里**响亮拒绝**（不是静默丢弃），把该块挪到主脚本
- **可嵌套**：`@if` 里能再写 `@if`/`@while`/`@Action`，裸 `@` 关闭最内层块——详见 [`@while` 循环块](#while-循环块)的「块嵌套」条与 [块嵌套与 @Include/@Merge](#块嵌套与-includemerge2026-10-12)
- `@Reflex` 反射矩阵与热 SQL 的瞬态 `Action` 表不带条件语义（`@if` 只在主脚本顶层生效）；`@Trigger`/`@Reflex` 条件反射的完整语义见下文专节

## `@while` 循环块

`@while(<条件>)` 是 `@if` 的循环同胞：块体与 `@Action`/`@if` 完全同构（列头 `<设备>.<参数>` + 数据行），**在当前线程内反复执行**——每轮先判条件、成立才把块体当 `@Action` 逐行派发、派发后回到判条件（是 `while` 而非 `do-while`：首次即假则零派发）；条件转假即退出，继续执行后续块：

```mt
@Vars
name  value;
   count  0;
@

@while(count<3)
sensor.reading;
  $count=reading;    # 捕获格每轮把读数写进 @Vars count，推进循环收敛
@
```

- **不开新线程**：与 `@Action`/`@if` 一样同步跑在调用线程，复用同一套派发（`dispatchMatrix`）与条件求值（`@Vars` 数值 / `@Alias` 文本）机制
- **条件每轮重求值**，读得到块体内**捕获格** `$var=field` 写进会话覆盖层的新值——「捕获改 `@Vars` → 条件转假」是收敛的 idiomatic 手段（捕获值跨迭代留存，作用域仍是本次 `run()`，结束整体回滚）
- **条件语法与 `@if` 完全一致**：比较 `> < >= <= == !=` 与逻辑 `&& || !`，类型严格无隐式真值——`@while(count)` 不是「非零即真」，要写 `@while(count>0)`；只引用 `@Vars`/`@Alias`，实时传感器值走守护采样链路（[docs/daemon.md](daemon.md)）
- **块头内不能有空格**（与 `@if` 同约束：矩阵解析把空白当分隔）——写成 `@while(count>0)`，不是 `@while(count > 0)`
- **终止只靠条件转假或 Ctrl-C**：每轮循环顶部查一次停止标志，`SIGINT`/`SIGTERM` 及时跳出（stderr 注记 `[while] stop requested, exiting after N iteration(s)`）。**不设迭代上限**——静态真条件（如 `@while(1==1)`）且块体不含改变条件的捕获格即热循环，只能 Ctrl-C 中断，写这样的条件前请想清楚
- 退出注记：条件转假 `[while] condition became false, exited after N iteration(s)`；首次即假 `[while] condition not met: '<条件>', 0 iterations`
- **与 `@Action`/`@if` 按书写顺序交错执行**（同 `@if`）
- **@Merge 片段里不支持**：与 `@if` 同理（片段无独立执行位置），出现在片段里**响亮拒绝**
- **块嵌套（2026-10-12）**：`@if`/`@while` 现在可以互相嵌套、也可以嵌套 `@Action`，`@while` 里能再写 `@if`/`@while`。闭合模型是**扁平裸 `@` + 深度栈**：每个裸 `@` 关闭**当前最内层**的块（不是「第一个 `@` 关掉整段」），故内层块用自身的 `@` 收尾、外层块再用一个 `@` 收尾。**块体是子块序列**（不再是单张二维矩阵）：块体内的连续直接行合成为隐式 `@Action` 子块、显式 `@名字` 子块按**书写顺序**并入，执行器 `execSequence` 递归下钻、按书写序交错执行（`test/cpp/test_action_nesting.cpp`）。
  - **叶子块不能嵌套**：`@Action`/`@Alias`/`@Vars` 等叶子块内再写 `@名字` 会**响亮拒绝**（「叶子块 @X 内不能嵌套 @hdr」）——只有控制块（`@if`/`@while`）能有 children。
  - **深度上限 32**（`mt::kMaxBlockDepth`）：超限解析期拒绝；脚本结束（EOF）时仍有未闭合的块**响亮报错**（不再静默返回半截脚本），多余的裸 `@`（无待闭合块）同样报错。
  - **归并 ⟂ 嵌套**：`@Merge`/`@Include` 的归并操作数必须是**纯矩阵叶子表**，控制块（有 children）当归并操作数会被 `mergeTwo` 拒绝——归并与嵌套是两条正交能力，不得混用。子块内的 `@Merge` 走**位置局部归并**（见 [@Merge 内联归并](#merge-内联归并运行端动作脚本合并)）。
- 回归：`action_while_*`（`test/cpp/test_action_while.cpp`）覆盖块头解析、捕获推进收敛、零迭代、书写顺序交错、Ctrl-C 跳出、报错契约与 `@Reflex` 共存；`action_nesting_*`（`test/cpp/test_action_nesting.cpp`）覆盖 if⊂while、while⊂if、外层假跳过整棵子树、交错子块按书写序执行、内层假只跳内层、停止标志穿透各层；`matrix_*`（`test/cpp/test_matrix.cpp`）覆盖解析器的 children 树构建、交错、叶子不可嵌套、多余裸 `@`、深度上限、EOF 未闭合响亮报错

## `@Trigger` / `@Reflex` 条件反射（#34，2026-09-29）

> 与 [trigger 引用（前置调用）](#trigger-引用前置调用) 的 `trigger` **列**是两回事：
> 那是结构脚本里的流引用列（前置调用入边），本节是 `.mt` 里的两个矩阵块。

把「动作序列」与「何时触发」拆成两张表：`@Reflex` 定义反射（可参数化的动作序列），
`@Trigger` 逐行触发它们——相当于给脚本加一层「像函数调用传实参」的入口：

```
@Reflex
name   relay0.deg;
blink  $(bright);
blink  0;
@

@Trigger
trigger;
blink(bright=1);
@
```

- **`@Reflex`**：列 0 = `name`（反射名），列 1.. = 动作列（`<设备>.<参数>`，与 `@Action` 列头同构）；**同 name 多行 = 同一反射的多拍**，按行序执行。单元格语义与 `@Action` 是**同一份派发内核**：`$(...)` 表达式、`$var=field` 捕获格、`-` 继承照常可用。
- **`@Trigger`**：列 0 = `trigger`；每行一个触发行 `reflexName(k=v, k=v)`，`v` 是实参文本（`k=v` 两侧 trim），**无括号 = 无参数触发**，空行跳过（宽松）。实参以**临时别名**注入会话覆盖层（子作用域）——反射动作行里的 `$(k)` 即取实参值，**无论成败出口撤销**、不污染后续触发。这与 `run_action_script` 工具的 `vars` 是同一套机制（[agent.md](agent.md) 工具表 `run_action_script` 行的「调用时临时注入会话别名」）。
- **惰性**：没有 `@Trigger` 时 `@Reflex` 只是定义——不执行也不校验（反射行引用了未绑定变量也不报错）。
- **顶层豁免**：整棵顶层序列没有任何可执行块（`@Action`/`@if`/`@while`）时，有 `@Trigger` 则脚本仍合法（反射独立成立），否则照常报 `No @Action matrix found`。
- **只写主脚本**：`@Merge` 归并只从片段累加 `@Alias`/`@Vars`/`@Action`（见 [`@Merge` 内联归并](#merge-内联归并运行端动作脚本合并)），片段里的 `@Trigger`/`@Reflex` **不会进主脚本**；`@Include` 是内容拷贝，写在被拷贝文件里等效于写在原地。
- **报错契约**（halt-on-error，行号 = 矩阵数据行号）：`@Trigger` 存在但没有任何 `@Reflex` 定义；`@Reflex` 表没有定义行；触发行不以 `)` 结尾；参数非 `k=v` 形式；参数名不是安全标识符；同名参数重复绑定；触发引用了未定义的反射（报错点名已定义清单）。
- 回归：`test/cpp/test_robot_dispatch.cpp` 的 #34 段（惰性定义、实参绑定/撤销、未定义反射报错、多拍顺序）。

## controller 引用（转交任务）

某个硬件收到指令后先干一份活，再把结果转交给另一个硬件：

1. 先运行自己的 Lua 驱动 `call`
2. 框架把「该行元数据（跳过 `name` 与全部流引用列 `controller*`/`trigger*`）∪ 自己 Lua 返回表」发给 `controller` 指定的硬件变量
3. `controller` 支持 `-` 继承上一行；被引用方必须在结构脚本中先定义

两点框架级行为需要知道：

- **派发目标 `mode` 由框架独占**（在合并参数之后才写入）：转发 payload 里混着上游返回表的键，
  上游驱动返回 `{mode="print"}` 之类的键不会改写下游的派发目标
- **驱动的 `build`/`call`/`destroy` 必须返回非空表**：返回非表或空表 `{}`（含漏写
  `return`）会被判契约违反并中断，不会被静默当成成功。表里**若带** `result` 键，值必须
  是 `"OK"` 或 `"ERR"`（`"ERR"` 连同 `message` 触发 halt）；controller 转发语义的驱动
  （如 `Relay`/`Servo`）刻意返回**无 `result` 键**的数据表，同样合法（判据见
  [drivers.md](drivers.md) 的「返回值契约」节）。
  `result`/`message`/`mode` 三个键名另由框架保留，`.mt` 动作脚本不得用它们作参数列
  （`MtVars_Lua::rejectReservedKeys`，即 `--help` 里「安全约束」一条的代码正身）。

反方向的调用编排（先把别人的结果收集进来，再调用当前零件）见下一节 [trigger 引用](#trigger-引用前置调用)。

**多列（扇出）**：controller 之外放行编号列 `controller2`/`controller3`…（基名或基名+纯数字
后缀；`controller2x` 仍是普通元数据列），一行可声明多个转发目标：

- 按**列声明序**逐个转发，每个 controller 收到**同一份** payload「元数据 ∪ 自己返回表」——
  同一行的多个 controller **不接力**（controller1 的结果不进 controller2 的输入）；
  跨变量链式转发仍然可用：目标自己的 controller 列会在它被调到时照常生效
- **出现一个 ERR 即停止并返回**：不再转发给其余 controller，异常上抛整帧中断（halt-on-error）
- 全部成功时当前零件的返回值 = **最后一个** controller 的结果（单列与既有行为一致；
  顶层回显打印的也是它）
- 同一行的 controller 列指向同一目标在装配期拒绝（同 payload 双转发是配置错误）；
  controller 目标也不能是 `@Alias`/`@Vars` 标量（装配期拒绝）

## trigger 引用（前置调用）

trigger 列是 controller 列的镜像：controller 是**出边**（当前零件调完后把结果传走），
trigger 是**入边**（当前零件被调用之前，先运行 trigger 列指向的硬件变量，把结果收集进当前零件的输入）：

1. 当前零件每次被派发（play）时，框架先以**空参数**调用 `trigger` 列指向的硬件变量——
   这是一次语义完整的 play：触发器自身的行元数据照常并入其调用参数，它若也带 controller 列则转发链照常走
2. 触发器返回表经 `ensureOk` 契约检查（`result="ERR"`/非表/空表即整帧响亮中断）
3. 返回表以**触发器名字为键的子表**并入当前零件的调用参数：`data.<触发器名> = {…}`
   （多触发器互不踩键；如触发 MPU6050 后驱动按 `data.imu0.ACCEL_X` 取六轴读数）
4. 再运行当前零件自己的 Lua `call`

```sql
CREATE TABLE I2C (name String, path String);
INSERT INTO I2C (name, path) VALUES ('i2c-1', '/dev/i2c-1');

CREATE TABLE MPU6050 (name String, I2C String, address String);
INSERT INTO MPU6050 (name, I2C, address) VALUES ('imu0', '$i2c-1', '0x68');

CREATE TABLE Servo (name String, max String, min String, offset String,
                    controller String, trigger String, channel String);
INSERT INTO Servo (name, max, min, offset, controller, trigger, channel)
  VALUES ('s1', '90', '-', '-', 'pca9685-0', 'imu0', '0');   -- 每次出腿前先触发一次 imu0
```

要点与边界：

- `trigger` 支持 `-` 继承上一行；**被引用方必须先声明**（与 `controller` 同规则）。
  这条约束顺带保证整个 trigger/controller 调用图按构造无环——派发期无需环检测；
  `$` 式前向引用是数据引用列的专属能力，写在 trigger 列会被明确拒绝
- 触发器目标可以是 Lua 驱动变量或守护变量（守护的 `play` 返回最新采样快照，首帧未出时
  `count=0` 不是错误）；`@Alias`/`@Vars` 标量不能当触发目标（装配期拒绝——触发器经
  play 调用，必须返回结果表）
- 触发器只挂在 play 路径（含 controller 转发的嵌套 play 与 agent 的 `playQuiet`）；
  `read()`/`build`/`destroy` 一律不触发
- 触发器名不得与本表元数据列同名、不得用框架保留键 `result`/`message`/`mode`
  （装配期拒绝）；`.mt` 参数列不得占用触发器名（派发期 `rejectReservedKeys` 拒绝）
  ——触发器结果子表按触发器名并入调用参数，这些名字因此成为调用参数里的保留键
- 触发器数据在元数据与动作参数之后并入；controller 转发的 payload = 元数据 ∪ 自己返回表，
  **不含触发器子表**——输入侧数据要继续转发，须由驱动在返回表里显式回显
- 触发是同步调用：N 个设备都挂同一触发器 = 每帧 N 次触发调用，无帧内去重；
  高频采样场景请改用守护变量 + `$` 引用读快照，触发器留给「每次执行前必须新鲜测量/先干一件事」的编排

**多列**：trigger 之外放行编号列 `trigger2`/`trigger3`…（命名规则与 controller 相同），
一行可声明多个触发器，按**列声明序**逐个前置调用——某个触发器 ERR 即停止，其后的触发器
与当前零件都不再执行；返回表各自以触发器名字为键并入，互不踩键。同一行的触发列指向
同一目标在装配期拒绝。

回归：`trig_basic`（正值 + 顺序/到位观察面专段）与 `trig_forward`/`trig_scalar`/
`trig_reserved`/`trig_collide`/`trig_dollar`/`trig_param`/`trig_n6`/`trig_err`（负值）；
多列 `ctrl2_basic`/`trig2_basic`（正值 + 观察面专段）与 `flow_dup`/`flow_dupc`/
`flow_fwd2`/`flow_scalar2`/`trig_scalar2`/`ctrl2_err`（负值）。

## `$` 引用列

元数据列可以按值引用另一个硬件变量：值以 `$` 开头（如 `$imu0`），被引用方的 `read()` 快照字段实时合并进本变量元数据；**不带 `$` 的裸名一律按字面值**。`$` 指向未定义变量在 **build 前**（全部表装配完成后）显式报错；指向**标量**（如 Alias 的 JsonString）也会清晰报错——标量引用请走 `controller` 列（唯一例外是 `@Vars` 数值变量，见下节）：

```sql
CREATE TABLE Monitor (name String, src String);
INSERT INTO Monitor (name, src) VALUES ('mon0', '$imu0');   -- 引用守护 imu0
```

值也可写成 `$(<表达式>)`：对 `@Vars` 做算术并把结果填入该列（完整语义见 [表达式](#表达式-)）。结构脚本里 `(` 是分隔符，必须整体加引号写成 `'$(...)'`：

```sql
INSERT INTO Servo (name, max, min, offset, controller, channel)
  VALUES ('s1', '$(smax+5)', '-', '-', 'pca9685-0', '0');
```

与声明顺序相关的三点行为：

- `$` **允许前向引用**（可以指向声明在后的变量）：存在性校验在全部表注册之后、任何驱动 `build`
  之前统一执行——与 `controller` 列不同，后者要求被指向的变量必须先声明
- `$` 的取值是**每次播放时**的实时快照，不是声明时的值
- 销毁阶段（`destroy`）取「字面列 + 引用列的尽力而为快照」：引用仍存活则并入其快照，
  已被销毁则**只跳过该引用**，本变量的 `destroy` 照样会被调用

### 接口器件（总线）必须声明在器件之前

总线句柄 `fd` 与从机 `address` 不是字面列，而是器件行经 `$i2c-N` / `$uart-N` 从 `I2C` / `UART` 表的 `call` 快照拿到的。因此 **`I2C` / `SPI` / `UART` 表必须声明在挂载其上的器件之前**：器件 `build` 要用 `fd`，而 `build` 按声明序执行——总线写在后面前向引用时，器件 `build` 会在 `Invalid Argument: fd or address` 上失败（`robots/test/ref_bus_forward.sql` 为正身负值用例）。

这条约束同时是**销毁期 `fd` 有效性的来源**：`fd` 只由接口器件自己的 `destroy` 关闭，而倒序销毁 + 上面的声明顺序 ⇒ 接口器件最后关闭 `fd`，所有挂在它上面的器件在 `destroy` 期间（关断/断电/写寄存器这类去初始化）`fd` 始终有效。`$` 引用列因此必须在 `destroy` 阶段解析——若你把器件去初始化写成依赖 `fd` 的形式，请务必保证总线表在器件表之前。

## `@Vars` 命名数值变量

`@Vars` 与 `@Alias` 同构（列 `name` / `value`），但**仅支持 Number**：`value` 必须是数值字面量（整数/小数/带符号/科学计数法）或 `$(<表达式>)`（见 [表达式](#表达式-)），否则在注册期即报错。字面量按原文驻留、不做转换（与结构脚本 `Number` 列共用同一判定）；表达式在读取时求值。它有两种消费方式：

1. **结构脚本 `$` 数值常量**：元数据列写 `$<name>`，该列取变量的数值文本——这是唯一允许 `$` 指向标量的变量类型（`Alias` 等标量仍按上节报错）：

   ```sql
   CREATE TABLE Vars (name String, value Number);
   INSERT INTO Vars (name, value) VALUES ('v1', 10);
   INSERT INTO Vars (name, value) VALUES ('v2', 5);
   INSERT INTO Vars (name, value) VALUES ('smax', '$(v1+v2+75)');   -- 90
   CREATE TABLE Servo (name String, max String, min String, offset String,
                       controller String, channel String);
   INSERT INTO Servo (name, max, min, offset, controller, channel)
     VALUES ('s1', '$smax', '-', '-', 'pca9685-0', '0');   -- max 即 90
   ```

2. **动作脚本参数位替换**：沿用 `@Alias` 的规则，`dev.<name>` 的参数位用 `value` 替换成参数名（值被限定为 Number，故实际以第 1 种 `$` 常量用法为主）；参数位也可写 `$(...)` 表达式（产物即参数名，见 [表达式](#表达式-)）。`@Vars` 可在结构脚本定义，也可在 `.mt` 内联；**`.mt` 内联只允许新名字，与结构定义同名即报错**（防动作脚本改写结构硬件参数），同一动作脚本内重名同样报错。

与 `$` 对象快照不同，`@Vars` 不做字段合并，只把数值文本写到承载 `$` 的那一列；它无资源，`build`/`destroy` 为空操作。回归见 `vars_num`（正值）与 `vars_bad`/`vars_nonnum`/`vars_dup`/`vars_override`（负值）。

## 表达式 `$(...)`

`$(<expr>)` 的语法：`+ - * / %`、括号、一元正负、十进制字面量、**字符串字面量（`"x"`，支持转义，2026-10-13）**、标识符。**比较（`> < >= <= == !=`）与逻辑（`&& || !`，短路）产出布尔——仅 `@if(...)` 条件语境接受**（见 [`@if` 条件块](#if-条件块2026-10-10)）；`$(...)` 旧语境（数据格/列头/`@Vars` 值/元数据列）遇布尔结果显式拒绝。标识符的合法集合与 `'+'` 的含义**由操作数类型分派**（2026-09-20 设计评估）：

- **两个 `@Vars`（数值）→ 算术**：`$(v1+v2)` 是加法，行为与语义都不变
- **出现 `@Alias`（文本）→ 拼接**：`$(pfx+n)`（别名值 `"relay-"` + 变量真值 `2`）得到 `"relay-2"`；数值操作数以**真值文本**参与（`%.15g` 渲染，`2e3` 的真值是 `"2000"`、`0.5` 是 `"0.5"`）
- **除 `'+'` 外的运算符对文本无定义**：`$(a-n)`、`$(a*n)` 等清晰报错——只有 `'+'` 拼接

可用位置与对结果类型的接受度：

1. `@Vars.value`：`INSERT INTO Vars ... VALUES ('v3', '$(v1+v2+10)')`（`.mt` 内联可裸写 `v3 $(v1+v2+10)`）——**只收数值**（`@Vars` 是数值常量，别名参与即报错）
2. 结构脚本元数据列：`'$(v1*v2)'`（SQL 里必须整体加引号，否则 `(` 触发切词）——**只收数值**
3. `@Action` 单元格——**三处落点，全部派发期求值**（改绑后的别名、变量真值以运行时为准）：
   - **数据格**：产物为数值 → 数值参数（既有行为）；产物为文本 → **文本参数**（与 SQL 元数据列同型，驱动 Lua 侧无感；数字型参数收到非数字文本由驱动侧 `tonumber` 响亮报错）
   - **列头设备位**：`$(pfx+n).test` → 产物作为设备名候选，走与裸名**完全相同**的解析（命中别名再解一层，故 `$(p)` ≡ `p`；命中 `@Vars` 沿用设备位显式拒绝；未知名原样穿透、派发期按行号报错）
   - **列头参数位**：`dev.$(a1+a2)` → 产物即参数名，**不再解析**（参数名不是名字绑定）

规则与边界：

- **拼接的文本可来自别名与字符串字面量**：`$(...)` 内标识符是严格引用（未定义即抛）；要拼进字面文本，2026-10-10 起可直接写 `$("relay-"+n)`，此前须先定义成别名（如 `@Alias pfx = 'relay-'`，两种写法等价）
- **引用驱动/守护名报错**：表达式里没有驱动的一席之地（名字是拿来做算术/拼接的，不是拿来做播放的）
- **除零/取模为零** 明确报错；数值结果以 `%.15g` 格式化回写文本（整数不带小数点）；非有限值（inf/nan）在求值出口拒绝，拼接中的数值真值渲染同样拒绝（`inf` 不会变成文本 `"inf"` 混进名字）
- **惰性求值**：读取时才解析标识符，故支持**前向引用**；成环（`a=$(b+1)`、`b=$(a+1)`）由线程局部深度计数拦下并报 `circular @Vars`。`.mt` 内联 `@Vars` 不得覆盖结构定义（见上节），因此动作脚本无法借此改写结构侧表达式的取值
- **存在性校验**：元数据列表达式里的标识符与 `$name` 一样，在全部表注册后、任何驱动 `build` 之前统一校验（允许前向引用）；`@Vars` 侧的引用在首次读取（build/首帧）时报错；`@Action` 侧（数据格/列头）在派发期报错
- **转义**（2026-10-13）：字符串字面量支持 `\n`（换行）、`\t`（制表）、`\r`、`\\`（反斜杠）、`\"`（双引号），解析期解码成对应字节——`.mt` 单元格内不能写裸换行/分号（会截格/截行），要产出含换行的文本参数（如驱动收到的多行文本）就写 `$("line1\nline2")`；其余 `\x` 形态**响亮报错**（不静默吞反斜杠）
- **空格**：矩阵按空白切格，`$(...)` 内不得含空格；SQL 引号形式内空白是数据，可以写 `$(v1 + v2)`
- **深度上限**：括号嵌套（`$(((...)))`）与平铺运算符链（`1+1+1+…`，左深树的求值递归深度等于链长）分别设上限，超限都在解析期拒绝，不会打爆宿主栈
- **列头表达式不得含小数点字面量**：列头 `<device>.<param>` 恰好一个点的既有切分规则先把文本拦下——需要小数就先装进一个 `@Vars`
- 回归：`expr_num`（正值，三处都覆盖）与 `expr_undefined`（负值）；类型分派见 `dev_expr_head`/`dev_expr_param`/`dev_expr_cell`（正值：设备位拼接、参数位拼接、数据格文本参数）与 `dev_expr_minus`/`dev_expr_undefined`（负值）

## `@Merge` 内联归并（运行端动作脚本合并）

运行端动作脚本归并：主脚本用一张 `@Merge` 矩阵声明要并入的 `.mt`，mybot 解析主脚本后**就地展开**，后续注册与派发与手写大脚本完全一致。归并内核（`mtmerge_core`）由 `test_mtmerge.cpp` 白盒单测覆盖：

```
@Merge
path phase;
  scripts/test/include_a.mt  1;
  scripts/test/include_b.mt  2;
@

@Action
timer-0.delay;
  200;
  200;
@
```

> **历史注记（2026-10-12）**：`@Merge` 承接的是旧 `@Include` 的**归并**语义（相位补 `-`、设备集不相交、`@Alias`/`@Vars` 主从覆盖、`mtmerge_core` 内核）。`@Include` 这个名字被**重新定义**为「C 式内容拷贝」（见 [@Include 内容拷贝](#include-内容拷贝c-式顶层拷贝2026-10-12)）——两者是不同机制：`@Merge` 把目标**并进**累加器/下表，`@Include` 把目标内容**原样搬到**当前位置。仓库里原先用 `@Include` 做归并的脚本已全部机械改名为 `@Merge`。

- **归并语义**：`@Action` 两两归并（设备集相交报错、`phase` 滞后/提前、耗尽补 `-` 保持姿势、前导 `-` 未起拍跳过、负相位部分丢弃告警/全部丢弃报错）。主脚本没有 `@Action` 时首个 `@Merge` 目标顶替累加器（其相位无对齐目标不生效）。
- **顶层 vs 子块内**：**顶层** `@Merge` 走上面这套累加器机制（`@Alias`/`@Vars` 主从覆盖、合并 `@Action` 锚定、块重排）。**控制块 children 内**的 `@Merge` 走**位置局部归并**（见 [块嵌套与 @Include/@Merge](#块嵌套与-includemerge2026-10-12)）：把目标**纯矩阵**按声明序用 `mergeTwo`（同相位/设备集语义）并入**同序列里紧邻其下的那张叶子表**，随后 `@Merge` 块被消费掉；不重排块序、不折叠标量（子块内的 `@Merge` 目标只能是纯矩阵，携带 `@Alias`/`@Vars` 或控制块即响亮拒绝）。
- **片段递归合法**：顶层 `@Merge` 的片段可以再 `@Merge` 别的片段（终止性由「已展开文件表」保证——每个文件至多展开一次，自包含/互包含在第二次触达时终止）。被包含文件可以没有自有 `@Action`（纯标量片段、纯组合片段都合法）；整体没有任何 `@Action` 时由派发期报错。
- **include-once（`*.once.mt` 后缀）**：带此后缀的文件是「可复用片段」——被再次包含时**跳过**并打 stderr 注记，菱形依赖（两个片段共享同一个子片段）就此可表达；普通 `.mt` 重复包含仍**报错**（抓笔误）
  - 后缀放在文件上：片段自己声明复用策略，所有包含点免于各自记忆
  - 「多次出现」与「多次展开」是两回事——耗尽侧的 `-` 保持格会逐拍重放保持值，那是保持姿势语义，不是二次展开
- **主从覆盖（同名标量行）**：`@Alias`/`@Vars` 同名行「更靠近主脚本的定义获胜」（stderr 注记），片段互相之间同名仍报错。两条参数化通道由此组成：
  - **值通道**：片段用 `$(...)` 单元格引用旋钮（如 `$(amp)`），主脚本用同名 `@Vars` 改旋钮值，派发期对合并后的最终值求值
  - **设备绑定通道**：片段的 `@Action` 设备列写 `@Alias`（缺省绑定某台设备），主脚本用同名 `@Alias` 改绑，派发期解析到新设备（见 [设备列别名](#动作脚本mt)）
  - `@Action` 的设备列本身不参与覆盖——设备集相交依旧报错
- **`path` 列**：`.mt` 相对路径。词法规则：拒绝绝对路径、`..` 分量、空段与 NUL，只放行 `.mt`；`O_NOFOLLOW` 拒绝符号链接。
- **基准目录**：主脚本按输入通道取「脚本集合根」——`--input` 文件通道 = 脚本所在目录；agent 工具 `run_action_script` = `--scripts-dir`；stdin / TCP 无脚本位置 = 进程当前工作目录（上例的 `scripts/test/...` 前缀即 stdin 场景）。**片段以自身所在目录为基准**——库片段可整体搬移，不硬编码自己相对根的位置。
- **`phase` 列**（可选，缺省 0）：整数，范围 ±100000；写 `-` 继承上一行的相位（首行 `-` = 0）。相位沿包含路径线性叠加。
- **硬限制**：`@Merge` 数据行 ≤ 32（全树累计——它同时界定展开次数与递归深度，每层嵌套消耗一行；`@Include` 拷贝行**共享**这同一预算）、被包含文件字节总量 ≤ 8 MiB、单文件 ≤ 8 MiB。主脚本不含 `@Merge` 时行为逐字不变（fast path）。
- **信任边界（务必知悉）**：`--tcp` 下发的动作脚本此前无法触达本地文件，`@Merge`/`@Include` 是第一个例外——远端脚本可让宿主读取**基准目录树内**的 `.mt` 文件并作为动作执行。词法规则、行数/字节预算把读取面限制在该树内、总量有界（嵌套树每层消耗行预算），且文件内容不进报错文本（无从借报错探测）；但对公网暴露 `--tcp` 时仍应意识到这一新增的本地读取面。

### 设计边界：为什么「共享」用后缀标记、「特化」只做值通道

递归包含的完整设计空间里论证过三档方案（include-once / 覆盖式 / 参数化），本节的语义是其中的取舍结论：

- **菱形（共享）**交给 include-once：按**文件身份**跳过，能区分「同一片段再包含」（放行）与「两个不同片段撞设备」（仍报错）——按**名字身份**的覆盖式做不到后者，会把护栏溶解掉，故不采用。
- **特化**由两条通道分担（主从覆盖 `@Alias`/`@Vars`）：**值通道**——节拍级的身份是位置（已被相位机制定义），给行配名字要么不承担语义、要么把 @Action 变成标签索引系统并使相位代数失效，片段要暴露可调行为就用 `$(...)` 引用 `@Vars` 旋钮——值是天然的名字载体，且粒度是真正的「改一个数」；**设备绑定通道**（2026-09-19 补齐）——片段设备列写 `@Alias`，主脚本改绑，派发期解析穿透。设备绑定不与相位代数冲突：解析发生在派发入口，归并期仍按列头文本裁决，别名只是「列头文本 → 真名」的一层映射。
- **撞设备的两层防线**（设备绑定通道的代价面）：归并期 `checkDisjoint` 只见列头**文本**——两个不同别名指到同一设备它看不见；派发期解析后按 (设备, 参数) 查重补上这一层（同设备不同参数合法：合并进同一次 play）。两层合起来，三种碰撞形状（同名归并期抓、异名派发期抓、未知名派发期按行号抓）全部显式报错，无一静默。
- **同模板绑多设备**（同一主脚本里把一份模板实例化到多台设备）仍是参数化（include 行级绑定）的领地，作为独立提案——`include-once` 的「每文件至多展开一次」与别名「整脚本单一绑定」都使单实例绑定无法表达多实例。

### 设计边界：为什么运算与拼接都只发生在 `$(...)` 之内

`'+'` 的类型分派（两个 `@Vars` 算术、出现 `@Alias` 拼接，2026-09-20 设计评估）把完整设计空间里的其它岔路都否决了：

- **不引入裸 `+` 拼接语法**：裸单元格里 `a+b` 式拼接会让「算术写错位」（少写 `$()`）从报错静默变成拼接（`1+2` 变 `"12"`）；把拼接收进 `$(...)` 与算术同门，两类 composition 各有唯一入口——`$(...)` 组文本/算数、`-` 继承与字面量保持原样。
- **类型跟操作数走，不跟语法走**：没有「拼接专用运算符」（如 `.` 或 `..`）——`@Alias` 与 `@Vars` 是同名机制的两个实例（名字绑定 vs 数值常量），让 `'+'` 按操作数类型分派（全数值算术、出现文本即拼接）比新增记号更少特例，且既有 `$(v1+v2)` 语义零变化。
- **定义期（`@Alias` 值 / `@Vars` 值里写拼接）否决**：`Alias` 表求值时 `Vars` 可能尚未注册（跨表顺序依赖），且主从覆盖改绑发生在派发期——定义期拼接的结果无法跟随改绑，片段复用能力反而变弱。拼接只在 `@Action` 求值面（数据格/列头）发生，求值时机 = 派发期。
- **`@Vars` 值与元数据列维持只收数值**：`@Vars` 是数值常量（值语义被 H-1/P0-2 防线依赖——覆盖即改写结构定义），元数据列是结构侧文本；文本结果在这两处显式拒绝，拼接能力不外溢出 `@Action`。
- **`$(...)` 内不做字面量拼接、产物不递归解析**：标识符严格引用（拼接文本只能来自别名）使「拼接结果碰巧又是别名」的链式套娃天然有界；设备位产物按裸名规则只再解一层（`$(p)` ≡ `p`），别名值即使形如 `"$(…)"` 也只按文本查找——环无从建立。
- **`--tcp` 安全面零变化**：远端脚本本就可直接写真名/真值（别名与 `@Vars` 本就在同一份脚本里可达），表达式拼接不新增任何远端能力；文本参数与 SQL 元数据列同型（驱动侧 `tonumber` 校验语义不变）。

## `@Include` 内容拷贝（C 式顶层拷贝，2026-10-12）

`@Include` 现在是**纯内容拷贝**，语义像 C 的 `#include`：把目标 `.mt` 解析出的**顶层矩阵原样搬到** `@Include` 块所在的位置，不做任何归并/相位/主从覆盖。

```
@Include
path;
  scripts/test/header_once.mt;
  scripts/test/prologue.mt;
@
```

- **只拷贝、不归并**：目标文件的每个顶层矩阵（`@Action`/`@Alias`/`@Vars`/`@if`/`@while` …）按序插到 `@Include` 块的原位置，随后与主脚本其余块一起走正常的注册/派发。与 `@Merge` 的区别：`@Merge` 把目标**并进**一张表，`@Include` 把目标**平铺搬进来**。
- **控制块可原样搬运**：与 `@Merge` 片段拒绝 `@if`/`@while` 不同，`@Include` 是纯拷贝，能把目标里的控制块（含其 children）原样搬进来，由 `execSequence` 正常执行。
- **`path` 列，仅此而已**：只接受 `path` 列——`phase` 对纯拷贝无意义，出现即**响亮拒绝**并指引改用 `@Merge`；其它列名同样拒绝。词法规则与 `@Merge` 同一套（拒绝对路径、`..`、空段、NUL，只放行 `.mt`，`O_NOFOLLOW` 拒软链）。
- **只能出现在最外层**（像 C 的 `#include`）：出现在 `@if`/`@while` 子块内**响亮拒绝**（「@Include 只能出现在最外层」）——拷贝进来的块会被归并/执行序打散，嵌在子块里没有意义。子块内要归并动作表请用 `@Merge`。
- **递归以片段自身目录为基准**：被拷贝内容里若还有 `@Include`，以**该文件自身目录**为基准递归展开（库片段可整体搬移）。
- **允许重复拷贝、靠预算终止**：C 式拷贝**不设**「已展开文件表」（同一文件可被多次拷贝，与 `@Merge` 的重复报错不同）；自包含/互包含的拷贝靠**行数预算**（`@Include`/`@Merge` 共享 ≤ 32 行）在触达上限时**响亮终止**，不无限递归、不 OOM。字节预算同 `@Merge`（总量 ≤ 8 MiB）。
- 回归：`mtinclude_include_*`（`test/cpp/test_mtinclude.cpp`）覆盖原样拼接、片段相对递归、控制块搬运、拒绝 phase 列、拒绝子块内出现、自包含靠行预算终止。

## 块嵌套与 @Include/@Merge（2026-10-12）

`.mt` 从「扁平块」升级为「可嵌套块树」，同时把旧的 `@Include` 归并语义拆成 `@Merge`（归并）+ `@Include`（拷贝）两个正交机制。三者的交互约束集中在这里：

- **闭合模型：扁平裸 `@` + 深度栈**。每个裸 `@` 关闭**当前最内层**的块；控制块（`@if`/`@while`）可嵌套、可含 `@Action`，叶子块（`@Action`/`@Alias`/`@Vars`）不可再嵌 `@名字`（响亮拒绝）。深度上限 `mt::kMaxBlockDepth = 32`；EOF 时未闭合的块响亮报错、多余裸 `@` 报错——不再静默截断。
- **块体是子块序列**：控制块体内的连续直接行合成隐式 `@Action` 子块、显式 `@名字` 子块按**书写顺序**并入 children；执行器 `ActionRunner::execSequence` 递归下钻、按书写序交错执行（`@if` 假跳过整棵子树并注记跳过多少动作行；`@while` 每轮先查停止标志再判条件）。
- **归并 ⟂ 嵌套（核心不变量）**：`mergeTwo` 的操作数必须是**纯矩阵叶子表**——控制块（有 children）当归并操作数会被拒绝（其网格为空、体在 children，按网格行补 `-` 会静默丢弃 children）。归并与嵌套是两条正交能力，不得混用。
- **子块内 `@Merge` = 位置局部归并**：控制块 children 里的 `@Merge`，把目标**纯矩阵**按声明序用 `mergeTwo`（复用相位补 `-`、设备集不相交、拒绝控制块操作数）并入**同序列里紧邻其下的那张叶子表**；连续多个 `@Merge` 累加进同一张下表，随后 `@Merge` 块被消费、从序列移除，**块序保持书写序**（`execSequence` 的交错执行依赖此序）。目标文件必须只含纯矩阵：携带 `@Alias`/`@Vars`（子块内不注册标量）或控制块即响亮拒绝。归并 pass 递归下钻所有 children；子块内 `@Merge` 目标路径以**主脚本目录**为基准。
- **顶层 `@Merge` 机制不变**：仍是累加器式（`@Alias`/`@Vars` 主从覆盖、合并 `@Action` 锚定、块重排），与子块内的位置局部归并是两条独立路径。
- 回归：`matrix_*`（`test/cpp/test_matrix.cpp`，解析器 children 树/交错/叶子不可嵌套/多余裸 `@`/深度上限/EOF 未闭合）、`action_nesting_*`（`test/cpp/test_action_nesting.cpp`，执行器递归）、`mtmerge_merge_two_rejects_control_block_operand`（`test/cpp/test_mtmerge.cpp`，归并拒绝控制块操作数）、`mtinclude_merge_nested_*`（`test/cpp/test_mtinclude.cpp`，子块内位置局部归并的正/负路径）。

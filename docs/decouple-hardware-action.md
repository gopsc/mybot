# 硬件声明与动作脚本解耦设计

对应 Issue #1。本文档为该重构的详细设计，供评审定稿后分阶段实施。

## 背景与目标

当前单个 `.mt` 脚本把硬件声明（`@I2C`、`@PCA9685`、`@Servo`、`@Speaker`、`@Alias` 等）与动作脚本（`@Action`）混在一个文件里，带来四个问题：

1. 多份动作脚本重复整段硬件声明，修改接线需要同步所有脚本；
2. 相同动作无法在不同机型间复用；
3. 硬件声明占据脚本主体，动作本身反而难以阅读；
4. 程序生成动作（DRL/NN）时输出被大量声明内容污染。

目标是将两者拆分为可独立维护、可组合的文件：硬件接法描述一次，动作脚本只关心动作。

## 文件格式

| 后缀 | 内容 | 校验规则 |
| --- | --- | --- |
| `.hw` | 仅硬件声明矩阵 | 出现 `@Action` 即报错 |
| `.ac` | 仅 `@Action` 及其局部 `@Alias` | 出现硬件声明矩阵即报错 |
| `.mt` | 混合格式（现状） | 不做限制，完全兼容 |

校验依据文件后缀而非内容探测，规则简单、行为可预期。

## 加载流程

解析层不变，`MatrixParser` 仍逐字符解析出矩阵对象链表；改动集中在 `RobotStruct` 的装配阶段，由单次"解析+构建+执行"改为两阶段。

### 阶段一：loadHardware(source)

1. 解析全部矩阵对象（现有 `readMatrix`）。
2. 放弃现有的按文档顺序遍历（`createHardVars`），改为按类型分桶、桶间定序：

```text
@Alias → @I2C → 自定义Lua硬件 → @Servo → @Speaker → @MPU6050_BIND
```

桶内保持声明顺序。定序依据是既有的依赖方向：舵机引用控制器变量（如 PCA9685），PCA9685 属自定义 Lua 硬件并引用 I2C 变量，扬声器无依赖。拓扑排序可正确构建任意深度的引用链，引用未声明变量时立即报错。

3. 构建硬件变量字典 `M` 并激活（现有 `active()` 语义不变）。

### 阶段二：runAction(source)

1. 输入仅接受 `@Alias` 与 `@Action`。
2. 局部别名进入独立的别名表；执行期参数名解析顺序为**动作局部表优先，硬件全局表兜底**。
3. 逐行执行 `@Action`（现有 `run_drl_action`）；引用未声明的设备变量时报错（该校验已在缺陷修复中先行补入）。

## 接口与命令行

`RobotStruct` 现有生命周期保持不变，新增两个入口：

```cangjie
public static func loadHardware(input: InputStream): RobotStruct
public func runAction(input: InputStream): Unit
```

命令行新增参数：

| 参数 | 说明 |
| --- | --- |
| `--hw <path>` | 硬件声明文件 |
| `--ac <path>` | 动作脚本文件 |

二者至少提供其一；同时提供时先 `loadHardware` 再 `runAction`。仅通过标准输入管道输入时视为混合格式 `.mt`，走兼容路径，现有用法不受影响。

## Lua 驱动路径解析

驱动脚本路径现为写死的 `./modules/<矩阵名>.lua`，改为按以下优先级查找：

1. 环境变量 `BOT4CJ_MODULE_PATH`（冒号分隔多路径）逐项尝试；
2. `.hw` 文件所在目录的 `modules/` 子目录；
3. 运行时工作目录的 `modules/`（向后兼容）。

命中即停；全部未命中时报出已尝试的完整路径列表。

## 对 Issue 待确认项的建议结论

1. **`@Alias` 归属**：允许出现在两类文件中，作用域隔离。`.hw` 内定义为全局默认，`.ac` 内定义为动作局部别名，查找顺序局部优先。理由：个别硬件列也可能受益于别名，而动作参数别名是最主要的使用场景。
2. **多个 `@Action`**：允许，按出现顺序串行执行；`save()` 序列化保持原序。理由：将"起立""行走"等语义段落分开书写更接近脚本的使用直觉，实现成本为零。
3. **旧式单文件兼容**：永久保留。`.mt` 后缀即混合格式，不做任何破坏性变更。

## 迁移方案

1. 抽取 `scripts/robot-hw.hw`：一份完整的硬件声明，内容取自现有脚本的公共段落。
2. 现有动作脚本收敛为 `.ac`：`jump.ac`、`tilt-f.ac` 等，各含局部 `@Alias` 与 `@Action`，删除整段重复的硬件声明。
3. 运行示例更新：

```bash
./_run.sh --hw scripts/robot-hw.hw --ac scripts/jump.ac
# 或继续使用管道的旧方式
cat scripts/std.mt | ./_run.sh
```

4. 原有 `.mt` 一律不删除，迁移以新增为主。

## 风险与开放问题

- `save()` 对混合输入的序列化目前整体输出；解耦后是否需要按来源拆分输出，待阶段三前确定。
- MPU6050 守护线程在 `active()` 中启动，与加载阶段解耦后时序不变，预计无影响；实施时在树莓派上回归验证。
- 自定义 Lua 硬件若引用了动作文件中的运行期结果，不在本设计的支持范围内——硬件声明保持纯静态。
